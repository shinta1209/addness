# 受託ワークスキル(client-work)

受託仕事の3大作業をモード別にドラフト化する。**クライアントへの送信・納品・入稿は必ず人間が行う。**

## モード1: 広告台本・クリエイティブ制作
「広告台本作って」+ 商材情報(LPのURL・商品説明・ターゲット)で発動。

手順:
1. 商材のLP/資料を読み、訴求できる価値を洗い出す
2. **訴求軸×フック型のマトリクス**を作る
   - 訴求軸: 悩み解決 / ベネフィット / 権威・実績 / 限定性 / 共感ストーリー
   - フック型: 問題提起 / 意外な事実 / Before-After / 質問 / 断定
3. マトリクスから有望な3〜5案を選び、台本を書く

台本フォーマット(動画広告1本あたり):
```
■ 案名: (訴求軸×フック型)
■ ターゲット: 誰の、どんな瞬間に刺すか
■ フック(0-3秒):
■ 問題提起/共感(3-10秒):
■ 解決策=商品提示(10-20秒):
■ 証拠/実績(20-25秒):
■ CTA(25-30秒):
■ 画面指示: 各カットの映像イメージ
```
静止画バナーの場合: メインコピー3案+サブコピー+デザイン指示。

守ること:
- 薬機法・景表法に触れる表現(効果の断定、No.1根拠なし、「絶対」「必ず」)を使わない。怪しい場合は台本に⚠マークを付けて人間の判断に回す
- クライアントのトンマナ資料・過去に勝ってるクリエイティブがあれば必ず先にもらう

## モード2: LP・記事の制作・修正
「LP作って/直して」「記事書いて」+ 対象(URL・原稿・修正指示)で発動。

- 新規: 構成案(セクション見出し+各セクションの目的)→OKもらってから本文ドラフト
- 修正: 修正指示を箇条書きに分解→1件ずつ「変更前→変更後」の対比で提示→まとめて反映版を出す
- SEO記事: 検索意図の整理→見出し構成→本文。競合上位の構成をWebSearchで確認してから書く
- 成果物はこのリポジトリの `work/` 以下に保存し、ファイル名は `YYYY-MM-DD_クライアント名_件名.md`

## モード3: 日報・連絡文
「日報書いて」で発動。

- 入力: 今日やった作業(箇条書きでOK。Addnessの今日の完了タスクから拾うことも可)
- 出力: 日報フォーマット
```
【日報】YYYY/MM/DD 石山
■ 本日の作業
- (作業と成果を1行ずつ。数字があれば入れる)
■ 進捗状況: (予定に対して前倒し/順調/遅れ+理由)
■ 明日の予定
■ 相談・確認事項: (なければ「なし」)
```
- クライアント返信文: 相手のメッセージを貼ってもらい、「承諾/確認/交渉/お詫び」のトーン指定でドラフト2案(丁寧め/簡潔め)を出す

## 共通ルール
- クライアント名・単価・未公開の商材情報など機密は、コミットするファイルに書く前に必ず確認する
- 送信・納品・入稿・課金操作はしない(ドラフトまで)
- 過去の成果物(work/以下)を先に検索し、使える型があれば再利用する
