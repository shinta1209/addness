# 受託ワークスキル(client-work)

案件ごとにクライアントからもらう資料(マニュアル・過去成果物・参考クリエイティブ・レギュレーション)を取り込んで**案件カルテ**を作り、以後はカルテを参照して依頼された制作物をドラフト化する汎用ワークフロー。

**クライアントへの送信・納品・入稿は必ず人間が行う。AIはドラフトまで。**

## 全体像(3フェーズ)

```
フェーズ1 インテイク(案件開始時に1回) 資料をもらう → 読む → 案件カルテ生成 → 本人確認
フェーズ2 制作(依頼が来るたび)       カルテ+資料を参照 → 制作モードの型でドラフト
フェーズ3 学習(FB・修正が来るたび)   差分をルール化してカルテに追記
```

## 機密の扱い(最重要)

- **このリポジトリは公開**。クライアント資料・カルテ・成果物はすべて `clients/` 以下に置く。`clients/` はgitignore済みでコミットされない
- コミットされるファイル(SKILL.md・テンプレート等)にクライアント名・単価・未公開商材情報を書かない
- 迷ったら書く前に本人に確認する

## フェーズ1: 案件インテイク

「新しい案件」「案件登録」「この資料取り込んで」で発動。

手順:
1. `clients/<案件名>/materials/` を作り、もらった資料を保存する
   - ファイルはそのままコピー、チャット貼り付け・URLの内容は `.md` に落とす
   - 元資料は加工せず残す(原文が真実源)
2. materialsを**全部**読む
3. `templates/案件カルテ.md` に沿って `clients/<案件名>/案件カルテ.md` を生成する
   - 資料から分かることだけ書く。**推定で断定しない**
   - 資料に無い・曖昧な項目は「要確認リスト」に回し、クライアントにそのまま聞ける文面にする
   - 過去成果物・参考クリエイティブがあれば「勝ちパターン」に型を抽出する(構成・フック・訴求軸・口調)
4. カルテ全文をチャットに貼り、本人の確認を取る。修正が入ったら直す

## フェーズ2: 制作

「(案件名)の〇〇作って」で発動。案件名が曖昧なら `clients/` の一覧から確認する。

共通手順:
1. その案件の `案件カルテ.md` を必ず読む(NG表現・トンマナ・勝ちパターン・学習メモを反映)
2. 必要に応じて materials/ の元資料・過去の deliverables/ も読む(使える型は再利用)
3. 下の制作モードの型でドラフト
4. `clients/<案件名>/deliverables/YYYY-MM-DD_件名.md` に保存し、チャットにも全文貼る

### モード1: 広告台本・クリエイティブ制作

「広告台本作って」+ 商材情報(カルテ or LPのURL・商品説明・ターゲット)で発動。

手順:
1. 商材のLP/資料を読み、訴求できる価値を洗い出す
2. **コンセプト・企画設計の依頼**なら `clients/_shared/コンセプト設計メソッド.md` の逆算7ステップに従い、6項目評価でチェックする(CRの型は `clients/_shared/CR勝ちパターン分析.md` を参照)
3. 台本の量産なら**訴求軸×フック型のマトリクス**を作る
   - 訴求軸: 悩み解決 / ベネフィット / 権威・実績 / 限定性 / 共感ストーリー
   - フック型: 問題提起 / 意外な事実 / Before-After / 質問 / 断定
4. マトリクスから有望な3〜5案を選び、台本を書く(カルテの勝ちパターンがあればそれを優先)

台本フォーマット(動画広告1本あたり):
```
■ 案名: (訴求軸×フック型)
■ ターゲット: 誰の、どんな瞬間に刺すか
■ フック(0-3秒):
■ 問題提起/共感(3-10秒):
■ 解決策=商品提示(10-20秒):
■ 証拠/実績(20-25秒):
■ CTA(25-30秒):
■ 画面指示: 各カットの映像イメージ
```
静止画バナーの場合: メインコピー3案+サブコピー+デザイン指示。

守ること:
- 薬機法・景表法に触れる表現(効果の断定、No.1根拠なし、「絶対」「必ず」)を使わない。怪しい場合は台本に⚠マークを付けて人間の判断に回す
- カルテのNG表現・トンマナに従う。トンマナ資料・過去に勝ってるクリエイティブが無い案件は先にもらう(要確認リストへ)

### モード2: LP・記事の制作・修正

「LP作って/直して」「記事書いて」+ 対象(URL・原稿・修正指示)で発動。

- 新規: 構成案(セクション見出し+各セクションの目的)→OKもらってから本文ドラフト
- 修正: 修正指示を箇条書きに分解→1件ずつ「変更前→変更後」の対比で提示→まとめて反映版を出す
- SEO記事: 検索意図の整理→見出し構成→本文。競合上位の構成をWebSearchで確認してから書く

### モード3: 日報・連絡文

「日報書いて」で発動。

- 入力: 今日やった作業(箇条書きでOK。Addnessの今日の完了タスクから拾うことも可)
- 出力: 日報フォーマット(カルテに案件指定の書式があればそちら優先)
```
【日報】YYYY/MM/DD 石山
■ 本日の作業
- (作業と成果を1行ずつ。数字があれば入れる)
■ 進捗状況: (予定に対して前倒し/順調/遅れ+理由)
■ 明日の予定
■ 相談・確認事項: (なければ「なし」)
```
- クライアント返信文: 相手のメッセージを貼ってもらい、「承諾/確認/交渉/お詫び」のトーン指定でドラフト2案(丁寧め/簡潔め)を出す

## フェーズ3: 学習

クライアントのFB・修正稿・ダメ出しをもらったら:

1. こちらのドラフトと修正後の差分を取る
2. 差分を**ルール化**して、その案件のカルテの「学習メモ」に日付付きで追記する
   - 例: 「2026-07-10: 冒頭で商品名を出すのはNG→3秒フックの後に出す」
3. 案件をまたいで使える普遍的なルールだと本人が判断したら、このSKILL.mdの該当モードに昇格させる(本人の指示があった時のみ)

目標: **同じ指摘を二度と受けない**。

## 共通ルール

- 送信・納品・入稿・課金操作はしない(ドラフトまで)
- カルテを読まずに制作を始めない
- 取れてない情報は正直に「要確認」。推定で断定しない
- 成果物はチャットにも省略せず全部貼る
