# 曲分析スキル(song-analysis)

## 目的
作曲の引き出しを増やすため、1曲を「理論の言葉」で分解し、同じ技法の曲へ横展開し、
分析結果を `songs/` に資産として蓄積する。

## 2つのモード

| | ライト分析(デフォルト) | ガチ分析(「ガチで」「深掘りして」で発動) |
|---|---|---|
| キー/BPM/構成 | ✅ | ✅ |
| ディグリー進行 | サビ+特徴的なセクションのみ | **曲まるごと**(イントロ〜アウトロ、セクション内は小節の流れがわかる粒度) |
| 技法タグ+理論解説 | 主要技法のみ | 全技法+「なぜそう響くか」+コードの機能(T/S/D)の流れ |
| 感情マップ(各セクションが聴き手に何をさせるか) | - | ✅ |
| 自分の曲への使い方 | 1〜2個 | 技法ごとに具体的なレシピ化 |
| 類似曲探索 | 3〜5曲 | 5〜10曲(裏取り付き) |
| 移動ド練習メモ | ✅ | ✅+ベースラインの動きの観察 |
| アレンジ観察(楽器の役割・音の足し引き) | - | ✅ |

どちらか迷ったらライトで出し、最後に「ガチ分析に格上げもできます」と添える。

## 「サビ」の定義(最重要・全モード共通)
**「サビ」と言われたら曲中の全サビ族を対象にする**: 1番サビ / 2番サビ / 落ちサビ / ラスサビ / 大サビ、繰り返しごとの変化形すべて。
- 各サビを4段組ブロックで並べ、**サビ同士の差分**(コードの差し替え・転調・アレンジの引き算)を必ず明示する
- 1番と同型のサビは「1番と同型」と1行で済ませてよい(省略と未取得を区別する)
- 取れなかったサビは存在ごと無視せず「◯番サビ: 要確認」のブロックを立てる
- ラスサビだけ・1番だけで済ませるのは仕様違反

## サビ完全性チェック(途中切れ防止。1つのサビは頭から最後まで取る)
検索で拾ったサビ進行は**部分引用であることが多い**。以下を必ず実行する:
1. **歌詞でサビの全範囲を先に確定する**: 歌詞サイト/歌詞解説記事を検索し、サビの「最初の行」と「最後の行」を特定する(例: 1番サビ=「夜を抜けて」〜「けどきっと」まで)
2. **取れた進行を範囲と突き合わせる**: 進行の先頭・末尾が歌詞の先頭・末尾に対応しているか確認。**対応しない=途中まで**なので、末尾の歌詞断片をクエリに入れて追加検索する(例:「曲名 コード "最後の行の断片"」)
3. **小節数の妥当性チェック**: サビは通常8/16小節。取れたコード数×1〜2拍で換算して明らかに短ければ途中と判断する
4. それでも埋まらない部分は `(ここから先 要確認)` とブロック内に明示し、「サビの後半◯行分が未取得」と数えて報告する
5. **歌詞違いのサビに注意**: 物語曲(YOASOBI等)はサビごとに歌詞が違う。歌詞Aのサビと歌詞Bのサビを同一視して混ぜない。どの歌詞のサビから取った進行かを必ず記録する
6. **サビの2周構造・サビ内転調に注意**: 1つのサビが「同じ進行×歌詞違いの2周」(あの夢をなぞって)や「前半キーX→後半キーX+1の2段構造」(桜日和とタイムマシン)になることがある。歌詞の段落が変わっても次のセクション(間奏/2番Aメロ)に入るまではサビ。**前半だけ取って完了と判断しない**
7. **歌詞引用スニペットは部分引用と疑う**: 検索で出るサビ歌詞は前半だけの引用が多い。フル歌詞サイト(歌ネット/うたてん)でサビの全行数を確認し、「コードが取れた行数 / サビの全行数」を必ず数えて報告する。数えられない場合は「サビの終端未確認」と書く
8. **ソースの優先順位**: 本人提供のスクショ/コピペ >> コード譜サイト >> 分析ブログ >> 検索スニペット。食い違ったらスクショを正とし、ブログ側の装飾コード(add9/経過dim等)は「アレンジ音の可能性・音源で要確認」として差分を残す

## クイックモード「サビだけ」(「サビだけ取って」「サビの進行だけ」で発動)
引き出し集を高速で増やすための1曲5分モード。
- 取るもの: キー / BPM / **全サビ族**の実コード列+ディグリー+ベース音 / **歌詞アンカー(行頭の断片)** / 一番おいしい技法1つ / 確度
- 歌詞アンカーは「サビの歌い出し+コード」で追加検索して取る(例:「曲名 コード "歌い出し断片"」)。行単位の対応まででOK、音節単位はスクショが来たら確定
- 歌詞は断片アンカーのみ(全文は書かない)。理由: リポジトリはGitHub上にあるため歌詞全文の転載は著作権リスクがある。分析目的の短い引用に留める
- 保存: `songs/アーティスト_曲名.md` を「クイック(サビだけ)」として作成し、「フル分析に格上げするときに埋めるもの」チェックリストを残す
- 複数曲を頼まれたら1曲ずつ裏取りして順に出す(まとめて雑に出さない)

## 取得プレイブック(2026-07実測。ここに書いてある通りに動く)
- ✅ **通るルート: WebSearchのスニペット/AI要約**。コード譜サイトやブログの中身が検索経由でなら読める。
  クエリ順: ①「曲名 アーティスト サビ コード進行 キー BPM」→ ②足りない部分はコード名や歌詞断片を引用符で入れて再検索 → ③「曲名 何調 転調 解説」
- ❌ **全滅ルート(再試行しない)**: WebFetchによるコード譜サイト直接取得(ChordWiki/U-フレット/楽器.me/J-Total/music-chord/chord-rinne/Ultimate Guitar/Mazmazika)、Songle API、Wayback Machine、curl直叩き(プロキシの許可リスト外)
- 💯 **最強ルート: 本人のスクショ/コピペ**。歌詞アンカー付きのフル分析ができる唯一の手段。フル分析にはこれを依頼する
- dim7の異名同音に注意: 譜面の「Gdim」等は短3度ごとに同一構成音(Gdim7=C#dim7=Edim7=B♭dim7)。機能はベース音と解決先から判定する

## 解説スタイルルール(全モード共通・最重要)
読み手は音楽理論を一通り学習済み(ディグリー・セカンダリードミナント・転回形・借用和音は既知)。
**説明の主語は常に「音」。どの音が、どの音へ、何度で動くか(=声部の動き)で説明する。**

1. **構成音を必ず書く**: コード名だけで済ませない。例「C#dim7(C#・E・G・B♭)」
2. **解決先を音名で示す**: 例「C#→D(半音上)、B♭→A(半音下)。2声が半音で反行して次のDm7に収束する」
3. **共通音と動く音を区別する**: 「FとAは鳴りっぱなし、動くのはベースだけ」のように、止まっている声部も情報として書く
4. **理論の別名・正体を明かす**: 例「C#dim7はA7(♭9)のルート省略形=VIm7へのセカンダリードミナント」。学習済みの概念と接続する
5. **曲中の位置に必ず紐付ける**: 「イントロ後半、歌が入る直前の2コード」のように、音源のどこを聴けば確認できるかを書く。特定できない場合は書かない(でっち上げ禁止)
6. **各技法に検証手順を1つ添える**: 「ピアノでC→Dm7と C→C#dim7→Dm7 を弾き比べる」のような、鍵盤で30秒で確かめられる手順
7. **比喩は原則使わない**。使う場合は1分析に1つまで、かつ音の説明を終えた後の補助としてのみ
8. ディグリーと実コードは必ず併記(移植可能性のため)

## 入力
- 必須: 曲名(できればアーティスト名も)
- 任意: 深さ指定(ガチ/ライト)、特に知りたいポイント(例:「サビの転調だけ」)
- 曲が特定できない場合は、候補を挙げてユーザーに確認してから進む(勝手に別の曲を分析しない)

## 手順

### 1. 情報収集(WebSearch)
- 「曲名 アーティスト コード」「曲名 キー BPM」「曲名 コード進行 分析」で検索する
- U-フレット等のコード譜サイト、音楽分析ブログ、Tunebat等のキー/BPMデータベースを**必ず複数ソース照合**する
- **ソースが1つしか見つからない項目は「要確認」と明記する**(コード譜サイトは誤りがある)
- 歌詞の全文転載はしない(著作権)。ただし**位置アンカーとして短い断片(1行あたり数語程度)をコードと並べて引用するのはOK**(分析・解説目的の引用の範囲)
- **フォールバック**: コード譜サイトがボットブロック等で読めず全セクションを埋められない場合、
  ①取れた範囲で分析を出し、取れなかったセクションは表に「要確認(ソース未取得)」と正直に書く
  ②ユーザーに「U-フレット等のコード譜をコピペしてくれれば100%版に更新できます」と依頼する
  ③コピペをもらったらディグリー変換・技法分析はこちらで全部やる(コピペ内の歌詞は保存ファイルに残さない)

### 2. 基本情報の整理
- キー(転調があれば全部)、BPM、拍子、曲構成(イントロ→Aメロ→…)

### 3. コード進行のディグリー分析
- セクションごとにコード進行をローマ数字(ディグリー)に変換する
- 例: `C→G→Am→F` in C major → `I→V→VIm→IV`
- 頻出進行には名前を付ける(王道進行 IV→V→IIIm→VIm / 丸サ進行 IVM7→III7→VIm7→I7 / カノン進行 / 小室進行 VIm→IV→V→I など)

### 4. 技法タグ付け+理論解説
以下の観点でチェックし、使われているものにタグを付け、「なぜそう響くのか」を1〜3行で解説する:
- **コード系**: ノンダイアトニックコード / セカンダリードミナント / 借用和音(サブドミナントマイナー等) / 転調(何調→何調、手法) / クリシェ / ペダルポイント / 分数コード・転回形 / sus4・テンション
- **メロディ系**: モチーフの反復・変形 / 順次進行と跳躍のバランス / コードトーン主体か経過音多めか / シンコペーション / 音域の使い方(サビで最高音など)
- **構成系**: イントロの作り(サビ先出し等) / Bメロの機能 / Cメロ(ブリッジ)の有無 / 落ちサビ・大サビ / アウトロ
- タグ名は `songs/INDEX.md` の既存タグと表記を揃える(同じ技法に別名を作らない)

### 5. 自分の曲への使い方(レシピ化)
- 特徴的な技法ごとに「自分の曲でどう使うか」を書く
- 「最後にもうひと押し欲しいとき→V→V#経由で半音上転調」のように、**使う場面→手順**の形式にする

### 6. 同じ技法の曲を探す(横展開)
- その曲の最も特徴的な技法(ユーザー指定があればそれ)について、同じ技法の曲をWebSearchで裏取りして挙げる
- 各曲に「どのセクションでどう使われているか」の一言説明を付ける
- **ユーザーの既存リストを優先**: `歌えるようになる曲リスト.md`(42曲)、`songs/INDEX.md` の分析待ちキューにある曲が該当したら必ず明記する(歌える曲と理論がつながるのが一番価値が高い)

### 7. 移動ド練習メモ
- サビのメロディの階名(移動ド)の特徴をメモする(例:「サビ頭はソ→ド の完全4度跳躍」)
- 採譜の裏取りができない場合は「未採譜(ピアノで確認して追記)」と正直に書く。推測で階名を断定しない
- テンポが速い曲は練習用の推奨テンポも書く

### 8. 保存(引き出し集への蓄積)
- `songs/_TEMPLATE.md` の形式で `songs/アーティスト名_曲名.md` に保存する
- `songs/INDEX.md` を2箇所更新する: ①技法→曲の逆引き表に追記(既存タグ行があればそこに曲を追加)②分析待ちキューのチェック
- 同名ファイルが既にある場合は上書きせず、差分を確認してから更新する

## 出力形式(チャットへの回答もこの順で)
1. 基本情報(**キーとBPMは必ず冒頭に明記**。転調がある場合はセクションごとのキーも)
2. セクション別の「歌詞アンカー付き進行表」+解説(下記書式)
3. 技法タグと理論解説
4. 自分の曲への使い方(レシピ)
5. 同じ技法の曲リスト(既存リストの曲は★印)
6. 移動ド練習メモ
7. 保存先ファイルパス

### 進行表の書式(全ブロック必ずこの4段組。例外なし)
**すべての進行ブロックを「♪歌詞 / 実コード / ディグリー / bass」の4行セット**で書く。解説はブロックの直後:
```
♪ 誰しも──何処か──に
   B♭/D → G♭/E → E♭m7
   III/3 → I7/♭7 → VIm7
   bass:  D  →  F♭  →  E♭
```
→ 解説(この進行で何が起きているか。声部の動き・機能・狙い)

- 歌詞が無い/取れていない行も4段は崩さない。♪行に `(インスト)` `(歌詞アンカー未取得)` と書く
- ベース音が推定の場合は `C#(推定)` のように注記する(でっち上げない)
- 「どの歌詞のどの音節でコードが変わるか」まで分かる場合は──の位置で表現する

## してはいけないこと
- 歌詞の転載
- 裏取りなしの断定(コード譜は間違っていることがある。「要確認」を付ける)
- 採譜情報がないのに移動ドの階名を推測で断定する
- 音源ファイルの無断ダウンロード
- songs/ 内の既存分析の無確認上書き
- INDEX.mdに同じ技法の別名タグを増やす(表記ゆれ禁止)
