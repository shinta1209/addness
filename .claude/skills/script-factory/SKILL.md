# SNS台本量産スキル(script-factory)

このスキルは3モード構成(本人指定の主用途に対応):
- **モード1: 台本作成** — リール台本・フィード・キャプションの量産。**翻訳モード**(伸びてる参考台本→自分用に変換。実績のある作り方)と**ゼロ生成モード**の2系統。詳細は `style-guide.md`
- **モード2: 誘導施策** — プロフィール→DM/LINE→AI ONEへの導線設計、CTA文言、DMキーワード施策(⚠骨組みのみ。CTA導線の実物ヒアリング後に作り込む)
- **モード3: ストーリー運用** — 日次オンデマンド型(「今日のストーリー作って」+枚数)。方針=**教育とファン化**。`story-playbook.md`(教育全8STEP+ファン化+ワークフロー)に従い、`work/stories/進行ログ.md` で進捗管理。現在フェーズ1(フォロワー1000人まで・LINE誘導禁止)

## 前提(アカウント設定)
- **必ず最初に同ディレクトリの `account.md` と `style-guide.md` を読むこと**。account.md=プロフィールとペルソナ3人(①レン=学生 ②タカシ=会社員 ③ミサキ=シンママ)、style-guide.md=実台本11本から抽出したトンマナ・変換テーブル・シグネチャーフレーズ・CTAパターン
- ジャンル: ビジネス/AI系(AI活用・AIマネタイズ・業務効率化・副業)
- 台本1本につきペルソナは1人。指定がなければテーマに合うペルソナを選び、各台本に「どのペルソナ向けか」を明記する
- 一人称の実体験を最優先のネタ元にする(「Fableに業務を全部分析させてみた」等、実際にやったことベース)

## モード1の本流: 翻訳モード(参考台本→完成版)

**本人の実際のワークフロー**: 理想的な成果物(伸びている参考台本)を渡されるので、それを自分の発信内容・トーン・実績に合わせて変換する。これが基本形。

入力: 参考台本(1本〜複数。テキスト貼り付け or Obsidianのファイル指定)

手順:
1. `account.md` と `style-guide.md` を読む
2. 参考台本の構成を分解する(フック/自虐・共感/転機/実績/価値観/CTA)。**構成と感情の流れは崩さない**
3. style-guide.md の変換テーブルで置換する(私→僕、インスタ/SNS→AI、他人の実績→実績4タグ、贅沢自慢→時間と場所の自由、ノウハウリスト→マーケ用語)
4. 実績・体験は**事実のみ**(実績4タグ+本人から確認済みのエピソード)。参考台本側のエピソードを自分のものとして残さない
5. テロップ割りで整形する(1行=テロップ1枚、漢字4文字以上続けない)
6. 出力は「完成版全文」+「主な置換箇所の対比(参考→完成)」のセット。置換に迷った箇所は⚠を付けて本人判断に回す
7. `checklists/投稿前チェックリスト.md` を案内する

保存先: `work/YYYY-MM-DD_リール台本_◯本目.md`(参考台本の原文は公開リポジトリにコミットしない。出典パスのみ記す)

## モード1の補助: ゼロ生成モード(参考台本がないとき)
- 入力: テーマ(ざっくりでOK)。テーマも無い場合は直近の作業ログやAddnessの完了タスクから「発信ネタ候補を10個」先に提案する
- style-guide.md の共通骨格+シグネチャーフレーズで書き、翻訳モードの品質と見比べる

## リール台本の型(構成型ライブラリ・ゼロ生成モード用)
1本ごとに以下から型を変えて出す:
- **問題提起型**: 冒頭で痛みを言い当てる →「実は原因は〇〇」→ 解決策3つ → CTA
- **Before/After型**: 「〇〇に毎日2時間→今5分」→ やり方 → CTA
- **リスト型**: 「AIで消える作業5選」→ テンポよく列挙 → 保存喚起
- **反論型**: 「まだ〇〇してるの?」「〇〇は不要です」→ 常識を否定 → 根拠 → CTA
- **実演型**: 画面見せながら「実際にやってみます」→ 結果 → CTA

## 台本フォーマット(1本あたり)
```
■ タイトル案(3つ)
■ 型: (上記のどれか)
■ フック(0-3秒): ※最重要。スクロールを止める一文
■ 本編(3-25秒): カット割りごとにセリフ+画面指示
■ オチ/CTA(25-35秒): 保存・フォロー・コメント誘導のどれか1つに絞る
■ キャプション: 1行目フック+本文+ハッシュタグ(ビッグ3+ミドル4+スモール3)
■ 撮影メモ: 必要な素材・画面録画の有無
```

## ストーリー3枚構成の型
1. 問いかけ/共感(スタンプで参加させる) → 2. 中身(価値提供 or 日常) → 3. CTA(質問箱・リンク・次予告)

## 品質基準
- フックは「数字・意外性・断定」のどれかを含む
- 1台本1メッセージ(詰め込まない)
- 誇大表現をしない(「誰でも」「絶対」「月100万確実」等はNG。実体験の数字はOK)
- 生成後に必ず `checklists/投稿前チェックリスト.md` を案内する

## してはいけないこと
- 投稿の実行(投稿ボタンは必ず人間が押す)
- 事実でない実績・体験のでっち上げ(実績はユーザーに確認する)
- 他人の投稿の丸パクリ(参考にする場合は構成のみ)
